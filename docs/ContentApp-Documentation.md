# ContentApp — техническая документация

Android-приложение (Kotlin + Jetpack Compose): пользователь вводит короткую
фразу-желание, приложение через ИИ разворачивает её в детализированный промт,
показывает подтверждение и генерирует изображение.

**v1** — без регистрации, оплаты и уровней доступа. Версия документа
соответствует состоянию проекта после удаления этого функционала (см.
`docs/DECISIONS.md`, раздел "v1 — упрощение"). Полная версия с монетизацией
сохранена отдельно в `ContentApp_v0.zip`.

---

## 1. Обзор

Пользователь вводит короткую фразу ("собачка на траве"), приложение
разворачивает её в детализированный промт через Gemini API, показывает
подтверждение и генерирует изображение той же моделью Gemini. Единственная
модель на всех — без вариаций по качеству, без водяного знака.

## 3. Внутренняя архитектура приложения

### 3.1. Единый источник состояния

`AppNavigation` — корневой компонент, держит состояние текущего запроса
(`lastPrompt`, `resultImageBytes`, `contentErrorMessage`, `isLoading`,
`saveMessage`/`saveIsError`) и создаёт единственные экземпляры сервисов
(`PromptExpansionService`, `ImageGenerationService`). Экраны (`MainScreen`,
`ResultScreen`) получают готовые колбэки и не содержат бизнес-логики.

### 3.2. Граф навигации

| Маршрут | Экран | Переходы |
|---|---|---|
| `main` | `MainScreen` | → `result` (по одной из двух кнопок фиксации промта) |
| `result` | `ResultScreen` | → назад на `main` ("Новый запрос") |

### 3.3. Разворачивание промта (P1) и генерация изображения (P4)

Обе стадии используют один и тот же `GEMINI_API_KEY` из `local.properties`.

- **P1** — `GeminiPromptExpansionService` вызывает Gemini (`gemini-2.5-flash`)
  с текстом (и фото, если приложено), возвращает развёрнутый промт для блока
  "Я правильно поняла?" (`S1.C1`).
- **P4** — `GeminiFlashImageGenerationService` (наследник
  `BaseGeminiImageGenerationService`) вызывает Gemini
  (`gemini-2.5-flash-image`, "Nano Banana") с зафиксированным промтом,
  возвращает байты изображения напрямую — без постобработки.

## 4. Реализованные экраны

### 4.1. MainScreen (S1)

Сверху — плашка с названием приложения (`S1.T0`, компонент `AppNameBanner.kt`,
во всю ширину, временный текст "MyApp"). Ниже — подпись "Что хочу" над полем
ввода промта (`S1.F1`, во всю ширину), под ним в ряд кнопка-скрепка
(`S1.B1`, приложить фото) и кнопка Enter (`S1.B2`) — обе делят ширину поровну,
единый размер со всеми остальными кнопками экрана (44dp). После Enter
появляется блок "Я правильно поняла?" (`S1.C1`) с редактируемым текстом
(`S1.F2`, увеличенной высоты) и двумя кнопками фиксации ("Сделать как я хочу"
/ "Сделать как ты поняла"). Ниже блока — пустое пространство (открытый вопрос,
см. `NEXT-STEPS.md`).

### 4.2. ResultScreen (S2)

Та же плашка `S1.T0` сверху (переиспользуется `AppNameBanner.kt`). Дальше —
"карточка в контексте": промт отображается полностью, ниже — результат
генерации (или сообщение об ошибке), кнопки "Сохранить" и "Новый запрос".

### 4.3. LoadingOverlay (O1)

Оверлей ожидания результата поверх текущего экрана (не отдельный переход) —
используется и на P1 (внутри `MainScreen`), и на P4 (поверх `ResultScreen`).

## 5. Что реализовано и что осталось

### Реализовано
- Полный UI-каркас двух экранов на Jetpack Compose (S1, S2).
- Разворачивание промта через Gemini API (P1), с учётом приложенного фото.
- Генерация изображения через Gemini API (P4).
- Сохранение результата в галерею через `MediaStore` (`ImageSaver.kt`).
- Единая цветовая палитра и типографика (`ui/theme/`).

### Открытые вопросы (см. `docs/NEXT-STEPS.md`)
- Точный дневной лимит бесплатного тарифа Gemini — уточнить в консоли.
- Дальнейшая доработка экранов и API — по ходу обсуждения в чате.

## 6. Как открыть проект

1. Распаковать архив.
2. Android Studio → **File → Open** → выбрать папку `ContentApp` (где лежит
   `settings.gradle.kts`).
3. Скопировать `local.properties.example` в `local.properties`, вписать
   `GEMINI_API_KEY`.
4. Дождаться Gradle sync (нужен интернет для загрузки зависимостей).
5. Запустить на эмуляторе/устройстве.

Требования: Android Studio Koala или новее, JDK 17.

## 7. Материалы этапа проектирования (`design/`)

Вайрфреймы и схемы из `design/` относятся к v0 (включают экраны входа/оплаты,
которых в v1 больше нет) — оставлены как исторический материал этапа
проектирования, не отражают текущий код:

- `main-screen.svg`, `login-screen.svg`, `loading-overlay.svg`,
  `result-screen-registered.svg`, `result-screen-unregistered.svg`,
  `main-screen-attach-icon.svg` — вайрфреймы экранов.
- `data-model.mermaid` — модель данных.
- `api-routing-flow.mermaid` — логика роутинга запросов для
  авторизованного/гостя.
