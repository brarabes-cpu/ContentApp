# TESTING CHECKLIST — что проверить при первом реальном запуске

Список ниже — по порядку: сначала то, без чего приложение вообще не
соберётся/не запустится, потом функциональность по экранам.

**v1** — без регистрации, оплаты и уровней доступа. Пункты про вход, профиль,
Google Play Billing, ЮKassa и водяной знак (были в v0) убраны — см.
`ContentApp_v0.zip`, если понадобится вернуться к ним.

## 0. Подготовка перед первым запуском

- [ ] Скопировать `local.properties.example` → `local.properties`
- [ ] Вписать `GEMINI_API_KEY` (получить на https://aistudio.google.com/apikey — без карты)
- [ ] File → Sync Project with Gradle Files
- [ ] Build → Rebuild Project — проверить, что сборка вообще проходит без ошибок

## 1. Сборка и запуск (S1 открывается)

- [ ] Приложение устанавливается на эмулятор/устройство без ошибок AAPT/Gradle
- [ ] Иконка приложения отображается в лаунчере (не серый квадрат-заглушка)
- [ ] При запуске сразу открывается главный экран (`S1`), без крашей
- [ ] Сверху видна синяя плашка с названием "MyApp" (`S1.T0`), во всю ширину экрана

## 2. Главный экран — ввод и разворачивание промта (`S1`, `P1`)

- [ ] Поле ввода (`S1.F1`) — на всю ширину экрана, принимает текст, плейсхолдер
      виден, пока поле пустое
- [ ] Под полем ввода — кнопка-скрепка (`S1.B1`) и кнопка Enter (`S1.B2`),
      одного размера, делят ширину экрана поровну
- [ ] Кнопка-скрепка (`S1.B1`) открывает системный Photo Picker
- [ ] После выбора фото кнопка-скрепка заменяется превью — видно само фото,
      не просто галочку
- [ ] Тап по превью — снова открывается Photo Picker (замена фото); выбор
      нового фото обновляет превью
- [ ] Крестик поверх превью (`S1.B8`) убирает фото — возвращается кнопка-скрепка
- [ ] После удаления фото (`S1.B8`) и повторной генерации (`P1`) промт
      разворачивается без фото — как будто его не было
- [ ] Кнопка Enter (`S1.B2`) с непустым текстом запускает разворачивание —
      появляется `LoadingOverlay` поверх экрана
- [ ] **Ожидаемое время ответа Gemini — обычно несколько секунд**; если долго
      висит — проверить интернет на эмуляторе и правильность `GEMINI_API_KEY`
- [ ] После ответа появляется блок "Я правильно поняла?" (`S1.C1`) с
      развёрнутым текстом в редактируемом поле (`S1.F2`, увеличенной высоты —
      видно больше текста без прокрутки, чем в исходном поле `S1.F1`)
- [ ] Если `GEMINI_API_KEY` пустой или неверный — под полем ввода появляется
      понятная ошибка красным текстом, а не краш
- [ ] Повторить тест **с приложенным фото** — Gemini должна учитывать его в
      разворачивании (проверить на глаз, что текст стал релевантнее содержимому фото)

## 3. Генерация изображения (`P4`) и результат (`S2`)

- [ ] Та же плашка "MyApp" (`S1.T0`) видна сверху и на `S2`

- [ ] Нажатие "Сделать как я хочу" (`S1.B3`) — переход на `S2`, поверх
      экрана `LoadingOverlay`, пока генерируется изображение
- [ ] Нажатие "Сделать как ты поняла" (`S1.B4`) — то же самое, но с
      отредактированным текстом
- [ ] После генерации на `S2.C1` показывается настоящая картинка (не текст-заглушка)
- [ ] Если генерация не удалась (например, превышен дневной лимит Gemini) —
      видно текстовое сообщение об ошибке на месте картинки, не краш

## 4. Сохранение результата (`S2.B1`, `P12`)

- [ ] На Android 10+ (API 29+) нажатие "Сохранить" сохраняет картинку в
      галерею сразу, без запроса разрешений
- [ ] На Android 8-9 (API 26-28), если разрешения ещё нет — сначала
      появляется системный диалог запроса `WRITE_EXTERNAL_STORAGE`
- [ ] После сохранения под кнопками появляется сообщение "Сохранено в
      галерею" (или текст ошибки, если что-то пошло не так)
- [ ] Картинка реально появляется в галерее устройства/эмулятора (альбом
      "ContentApp" в Pictures)
- [ ] Отказ в разрешении (API 26-28) — под кнопками сообщение об ошибке,
      не краш

## 5. Новый запрос (`S2.B2`)

- [ ] Возвращает на главный экран (`S1`)
- [ ] Поле ввода (`S1.F1`) и блок "Я правильно поняла?" (`S1.C1`), если он
      был открыт, остаются заполненными — это ожидаемое поведение, не баг

---

## Как сообщать о багах в чат

Проще всего — указать ID из `SPEC.md` и что пошло не так, например:
"на S1.B2 приложение крашится" или "S2.C1 показывает пустой экран вместо
ошибки". Так не нужно будет заново объяснять контекст.
